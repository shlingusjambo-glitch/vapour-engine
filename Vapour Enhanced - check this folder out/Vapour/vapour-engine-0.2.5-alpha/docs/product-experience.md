# Product experience

Vapour has two related interfaces with different density requirements.

## Hub and documentation

The Hub is a calm light workspace: warm near-white canvas, black and graphite
type, hairline borders, compact mono labels, restrained rounding, generous
spacing, and one dark primary action. It borrows the supplied design references'
shared principles—typographic clarity, product-first restraint, warm paper
surfaces, terminal precision, and minimal elevation—without copying another
product's trademarks or exact composition.

The default website route is the Hub. It owns recent projects, project creation,
disk and origin-private workspaces, installed editor versions, learning entry
points, and project-to-editor transitions.

## Editor

The editor is a dense dark professional tool because long authoring sessions and
high information density need a different surface from the Hub. Its canonical
layout follows the supplied Unity workspace reference:

- hierarchy and search on the left;
- Scene/Game viewport and tool modes in the center;
- component inspector on the right;
- assets, console, and profiler along the bottom;
- play controls, transform tools, snapping, and status kept visible;
- selection, edits, undo/redo, and viewport feedback update in real time.

Vapour will pursue behavioral parity for common authoring workflows, while its
visual identity, browser-native constraints, WebGPU diagnostics, and terminology
remain its own. Controls are only exposed when wired to real state; planned
features do not appear as decorative buttons.

## Shared rules

- System sans is used for reading; monospace is used for commands, versions,
  paths, profiler values, and machine-oriented metadata.
- Hierarchy comes from value, spacing, and hairlines rather than decorative
  gradients or large shadows.
- Vapour's cool mist accent is sparse and functional: selection, focus, active
  tools, and renderer status.
- Error states explain the failed capability and remediation rather than leaving
  an empty viewport.
- Keyboard access, focus visibility, reduced motion, and narrow-window layouts
  are product requirements, not finishing polish.
